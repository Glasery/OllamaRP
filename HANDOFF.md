- Язык общения и комментариев в коде — русский. Пользователь не разработчик: объясняй
  результат и риски простыми словами, коротко, без воды.
- Запуск/тесты только из venv: `venv\Scripts\python.exe test_logic.py` (88 тестов, все зелёные
  на момент передачи). Статический анализ: `venv\Scripts\python.exe -m pip install pyflakes`
  → `-m pyflakes *.py` (должен молчать).
- Живые проверки интерфейса — `tools\probe_*.py` (поддельный Ollama-сервер, см. `tools\README.md`);
  каждый должен печатать `ИТОГ: багов: 0` и `исключений Tk: 0`. Скриншоты окна — через `ImageGrab`
  (окно приложения может оказаться под другими; делай `attributes("-topmost", True)` на время кадра).
- Никогда не трогай данные пользователя в `%APPDATA%\OllamaRP` (пробы работают на временной папке).
- Если пользователь говорит «пока ничего не применяй, давай теоретически» — только обсуждение.
- Коммит/push — **только по просьбе**. Коммиты подписаны `Glasery <32816751+Glasery@users.noreply.github.com>`;
  `git push origin main` работает (учётные данные сохранены). Предупреждения про LF/CRLF — норма.
- Ловушка среды: bash-heredoc и `sed` портят экранирование (`\n`, `\\`, кавычки). Для правок кода
  надёжно: писать скрипт-патч файлом через инструмент Write (с `assert s.count(old) == 1`) или
  использовать Edit; не вставлять многострочный код с `\n` через heredoc.
- После любой фичи: тест на чистую логику в `test_logic.py`, живая проба, обновить `README.md`,

## Что сделано (кратко; детали — в PROJECT_CONTEXT.md)
Режимы Диалог / **Группа** / История / Чат; пресеты (герой, персонаж, **второй персонаж**, локация,
сценарий, конфиг-промпт); память диалога (слои, сводки) и **динамическая память персонажа**
(5 разделов в JSON, дельта-режим, 3 состояния Выкл/Чтение/Обновление, лимит в Settings);
фото: аватар / галерея / эмотиконы поверх интерфейса (Windows, 3 режима кнопки);
сохранения диалогов (`sessions*.py`); защита от зависаний (`stall_timeout`, `think_timeout` +
лестница повторов без размышлений); устойчивость к битым данным (карантин `.corrupt-*`,
нормализация снимков); английские стартовые пресеты; экспорт txt/docx.

### Режим «Группа» (самое свежее)
Два персонажа + герой-наблюдатель. Один запрос = одна реплика; ответ — JSON `{To, action, speech}`
(`To` — enum из имён участников + «все»; заглавная, т.к. Ollama выдаёт поля по алфавиту;
пусто/«все» — адресат по обращению в тексте, `group_chat.guess_to`); следующего говорящего выбирает код (`group_chat.py`,
`gui.App._group_*`). Автодиалог / пауза / шаг, вмешательство героя, мьют одного персонажа
(тогда адресат только герой, автодиалог недоступен — алерт), случайная длина реплики на каждый ход
(`group_chat.pick_length`: short/medium/long; средняя длина - ползунок на панели «Сцена», 150..900,
по умолчанию 340 -> потолки речи 200/380/550 символов, всё масштабируется от него;
обрыв стрима >3500 символов, подрезка и дедупликация предложений, недописанный хвост оборванного
ответа убирается), обрезка «сценария» с подписанными чужими репликами в speech
(`group_chat.cut_foreign_lines`), подпись «Имя → Кому» в чате.
**Не проверено на реальной модели** — только на поддельном сервере: различимость голосов у 8B,
дрейф в комплименты/зацикливание в долгом автодиалоге, надёжность поля `to`. Скорее всего именно
здесь будут следующие правки по результатам реальных тестов пользователя.
