# Ollama RP

Выбор модели Ollama, конструктор сцены из независимых блоков (Главный
герой (Вы) / Персонаж / Локация / Сценарий / Конфигурационный промпт),
режим диалога и режим генерации истории, сохранение пресетов в JSON.
Окно нативное (CustomTkinter), браузер нигде не участвует.

На главном экране - только выбор пресета по каждому блоку и кнопка
«Настроить». Она открывает окно со списком пресетов этого типа, где их
можно создавать, редактировать и удалять. Пункт «—» в селекторе = блок
не участвует в промпте.

В форме правки пресета напротив каждого поля (кроме имени/названия —
имя всегда вводится вручную) есть кнопка **«Сгенерировать»**: отдельный
скрытый запрос к выбранной модели «придумай это поле». Уже заполненные
поля этого же пресета (имя, внешность, биография…) передаются модели как
контекст, чтобы результат с ними не спорил. Ответ подставляется в поле,
его можно править дальше или сгенерировать заново. Запрос и ответ видны в
панели Logs. Нужна запущенная Ollama и выбранная модель.

Три режима (таб-бар над центральной колонкой): **Диалог** (`dialogue`) /
**История** (`story`) / **Чат** (`chat`). Под таб-баром - однострочная
подсказка, что делает выбранный режим.

**chat** — голый чат, как `ollama run`, без ролплея: system-промпт НЕ
отправляется, сцена/персонажи/память отключены и скрыты, вкладка «Память»
тоже. Влияют только параметры вкладки **Settings** и сама модель — режим
для тестирования ответов при разных настройках без влияния промптов.
Левая колонка сразу показывает Settings, ввод — одно поле «Сообщение».
Официальный `think` (reasoning) в chat работает.

Левая панель в dialogue / story зависит от режима:

- **dialogue**: Главный герой (Вы) · Персонаж (ровно один) · Локация ·
  Сценарий · Конфигурация, плюс поле **Дополнительные детали**
  (произвольный текст сцены — уходит в промпт блоком
  «## Дополнительные детали»).
- **story**: Главный герой (Вы) · Персонажи (можно добавить несколько) ·
  Сценарий · Конфигурация, плюс **Размер истории** (выпадающий список из
  5 готовых вариантов — от «короткая сцена, 3–5 абзацев» до «максимально
  длинно и подробно, ~80–120 абзацев»; у каждого чёткий числовой диапазон
  вместо размытых формулировок — так модель держит объём надёжнее; «—» =
  не задавать) и поле **Дополнительные детали**. Блока «Локация» здесь
  нет - по ходу истории локации меняются.

«Главный герой (Вы)» - это персонаж, которым играет пользователь; модель
его не отыгрывает, но знает, с кем имеет дело.

Левая колонка - две вкладки: **«Сцена»** (всё вышеописанное) и
**«Настройки»** - параметры генерации (temperature, top_p, top_k, min_p,
repeat_penalty, repeat_last_n, num_predict, num_ctx, seed, стоп-строки,
reasoning вкл/выкл, keep_alive). У каждого поля - пояснение, зачем оно;
пояснения переносятся по ширине колонки (на весь экран занимают всё
доступное место). Во второй строке сверху, слева от списка активных
пресетов — бейдж **«Reasoning: enabled»** / **«Reasoning: disabled»**
(по `/api/show`): поддерживает ли выбранная модель официальные размышления.
Настройка **Reasoning** во вкладке «Настройки»:

- «как у модели» — модель с поддержкой думает автоматически, остальные
  не трогаем;
- «включить» — заставить думать: модель с поддержкой получит параметр
  `think`, модель **без** поддержки (напр. `*-Reasoning` GGUF с
  HuggingFace) — инструкцию в промпте рассуждать в `<think>…</think>`;
- «выключить» — запретить (для моделей с поддержкой; напр. `qwen3`
  думает по умолчанию).

Размышления (и из поля `thinking`, и инлайновые `<think>…</think>` из
текста) уходят в панель **Logs**, в чат — только ответ. Во время
генерации в верхней панели статус: ⏳ ждём → 💭 размышляет → ✍ отвечает.

Настройки применяются к **каждому** запросу - и в диалоге, и в истории;
пустое поле = параметр не отправляется, действует значение по умолчанию
модели. Лежат в `settings.json`, сохраняются по кнопке и при закрытии
окна. Кнопка **«Optimal»** возвращает все поля к рекомендованным
значениям для RP (`temperature 0.75`, `top_p 0.9`, `top_k 40`,
`min_p 0.08`, `repeat_penalty 1.05`, `repeat_last_n 64`,
`num_predict -1`, `num_ctx 8192`; seed/stop/reasoning не навязываются).
Мягкий `repeat_penalty` и узкое окно — намеренно: на русском высокие
значения провоцируют переход модели на английский и «ломаную» речь.
Эти же значения стоят по умолчанию при первом запуске - без захода на
вкладку. «Очистить» - обнулить всё (модель решает сама).

**Предпроверка контекста.** Перед отправкой приложение грубо прикидывает
размер запроса в токенах. Если он не влезает в `num_ctx` (что у
Mistral/Ministral даёт не «обрезку», а Jinja-ошибку «roles must
alternate»), появляется окно с выбором: **поднять `num_ctx`** до
ближайшей степени двойки, **сжать пример** (что бы ни было в истории —
диалог, история, доп. текст) или **продолжить как есть** на свой риск.

При «сжать пример» приложение берёт **самый крупный источник** — историю
чата **или** поле «Дополнительные детали» (туда обычно и вставляют
большой диалог, если хотят пересобрать его в историю). Целевой объём
сводки берётся **от `num_ctx`**: сжимается не «до минимума», а ровно
настолько, чтобы результат занял почти весь оставшийся контекст —
поэтому при большем `num_ctx` сохраняется заметно больше деталей (при 8k
итог ~15 % исходника, при 16k ~40 %). Пример режется на несколько кусков
(не больше ~2400 токенов вывода за запрос — чтобы шаг не был
многоминутным), каждый сворачивается отдельным скрытым запросом;
reasoning-моделей просят отвечать сразу, без `<think>`. В окне чата — строка «🗜 Сжимаю пример…», справа сверху счётчик
`i/n` и живой «~N слов» (или «модель думает…»), так что видно, что работа
идёт. Кнопка **«Стоп»** прерывает сжатие и берёт то, что уже готово.
Затем результат подставляется на место оригинала (историю заменяет
сводкой; текст в поле «Доп. детали» — тоже; оригинал хранится до конца
сессии) и **сразу запускается генерация** на сжатой основе.

На большой модели, которая не помещается целиком в видеопамять, сжатие
может занять несколько минут — это нормально, следи за счётчиком.

**Фото персонажей и героя — три независимых вида.** В «Настроить» у блока
«Персонаж» и у блока «Главный герой (Вы)» есть три необязательных набора
картинок, каждый включается своей галкой в Settings. Нужен пакет Pillow
(`pip install pillow`, он есть в `requirements.txt`); без него всё работает
как раньше, просто без фото. В промпт модели фото не попадают — только в
интерфейс. Файлы копируются в папку `photos` рядом с пресетами (оригинал не
меняется); лишние после замены или удаления пресета убираются сами.

1. **Аватар** (галка «Аватары: фото рядом с репликами в чате») — одно фото. В режиме
   «Диалог» рядом с репликами рисуется маленькая круглая аватарка: у
   персонажа — его, у ваших реплик — вашего героя. Верстка чата не меняется:
   аватарка — просто начало строки, текст идёт ровной колонкой правее.
2. **Галерея** (галка «Галерея: вкладки «Фото» в боковых панелях») — несколько фото. Они
   показываются ТОЛЬКО во вкладке **«Фото»** боковых панелей (режим «Диалог»):
   слева — галерея выбранного героя, справа — выбранного собеседника. Фото
   вписывается в панель целиком; если их несколько, внизу появляются стрелки
   «‹ ›» и счётчик «Имя · 2 / 5». При выключенной галке вкладки остаются, но
   неактивны.
3. **Эмотиконы** (галка «Эмотиконы поверх интерфейса (экспериментально, Windows)», **экспериментально,
   только Windows**, по умолчанию выключена) — PNG-силуэты на **прозрачном
   фоне**. Загрузить можно только такие: JPG, PNG без прозрачности и PNG со
   сплошным фоном отклоняются с предупреждением. Эмотиконы рисуются ПОВЕРХ
   интерфейса отдельными прозрачными окнами (настоящая попиксельная
   прозрачность): слева — героя, справа — собеседника, каждый по центру своей
   колонки. Нижний край у всех — **низ экрана**, поэтому они стоят на одном
   уровне и могут выходить за рамки приложения. Клики проходят сквозь них.
   В чате эмотикон меняется **на каждый новый ответ** по кругу (один
   эмотикон — не меняется); вручную переключать нельзя. Кнопка вверху
   переключает три режима по кругу: **«Эмотиконы: все»** → **«только
   собеседник»** (герой слева скрыт, левое меню свободно) → **«скрыты»** (оба
   убраны, доступны оба меню); подпись показывает текущий режим, выбор
   запоминается. Эмотиконы не показываются во вкладке
   «Фото». Высокие узкие картинки лучше: ширина ограничена колонкой, и чтобы
   чат не перекрывался, подбирайте силуэты соответствующих пропорций. Окна
   следуют за главным (двигаются, меняют размер, прячутся при сворачивании и
   в режимах «История» / «Чат»). Что-то ведёт себя странно — выключите галку.

**Стартовые примеры.** При первом запуске (когда пресетов ещё нет) создаются
примеры на русском и на английском: Ксана / Girl, «Я» / Me, «старинный
ресторан» / Old town, «свидание» / Sudden encounter, «базовые правила» /
Basic rules; при английском интерфейсе активными выбираются английские. Свои
пресеты в exe не входят — они хранятся в `%APPDATA%\OllamaRP`.

**Динамическая память персонажа.** В «Настроить» у персонажа (только
собеседник, не герой) есть галка **«Динамическая память персонажа»** и поле
с её текстом. Это краткий список самого важного, что с персонажем случилось и
как он изменился: ключевые события, отношения, статусы, внешность. Он хранится
в самом пресете, подставляется в промпт этого персонажа и переживает
отдельные диалоги — персонаж «помнит» прошлые встречи. Как это работает:
после того как память диалога собрала очередную сводку, **со следующего хода**
отдельным запросом в модель уходят новые сводки и текущая динамическая
память — с просьбой кратко обновить её (никогда не в тот же ход, где
собиралась память диалога, чтобы не ждать два запроса подряд). Если ничего
важного не произошло, модель отвечает «НЕТ_ИЗМЕНЕНИЙ», и память не трогается.
Размер ограничен (по умолчанию 4000 символов, настраивается в Settings — «Предел динамической памяти»): выше память не растёт — при переполнении
отбрасываются самые старые пункты; резкое «усыхание» памяти от слабой модели
отвергается. Текст можно править руками; кнопка **«Очистить динамическую
память»** (применяется после «Сохранить»). Нужна включённая память диалога
(Settings → «Размер истории» больше 0). При **сохранении диалога** с такой
памятью приложение спросит, обновить ли её: «Да» — сначала дособирается
память диалога (последние ходы), затем обновляется динамическая (это
единственный случай двух запросов подряд), и только потом диалог сохраняется;
«Нет» — сохранить как есть; «Отмена» — не сохранять.

**Сохранение диалога и продолжение позже.** Кнопка **«Сохранения…»** (под
«Экспорт…» в чате) открывает окно: введите название и нажмите «Сохранить как
новое» — текущий диалог запишется целиком: чат (с курсивом и аватарками),
история, бегущая память и пересказ, выбранные пресеты, режим, модель и даже
недописанные поля ввода. В списке у каждого сохранения кнопки «Загрузить»
(вернёт всё ровно с этого места, в том числе после перезапуска приложения),
«Перезаписать» (обновить тем же названием, когда продвинулись дальше) и
«Удалить». Загрузка заменяет текущий диалог (приложение спросит). Если пресет
после сохранения удалили, он вернётся из сохранения; если изменили — берётся
его актуальная версия. Нет модели из сохранения — останется текущая. Logs и
Settings в сохранение не входят. Во время генерации сохранять и загружать
нельзя. Файлы лежат в папке `sessions` рядом с пресетами (JSON, по файлу на
сохранение).

Если модель **зависла посреди ответа** (обычно на этапе «размышляет» —
токены перестали приходить), приложение само оборвёт запрос и отправит его
заново — до 3 раз, дальше покажет ошибку. Сколько секунд тишины считать
зависанием, задаётся в Settings: **«Таймаут „модель молчит“ (сек)»**,
по умолчанию 30, `0` — выключить. Таймер включается с первого полученного
токена, так что долгая загрузка модели и обработка длинного промпта до
начала ответа его не задевают, а пока модель шлёт токены (думает или
пишет) — он не срабатывает. Перезапрос виден в статусе генерации и в Logs
(заголовок капсом), в самом тексте диалога/истории пометок нет.

Выпадающий список моделей запоминает выбор: при следующем запуске
активной встанет та же модель, что была выбрана в прошлый раз (а не
первая по алфавиту/дате установки, как раньше). Сохраняется сразу при
выборе в меню — не нужно жать «Сохранить» в Settings или ждать закрытия
окна.

Рядом с кнопкой «Обновить список» — **«О приложении»** (что за система,
что умеет, три режима, память, приватность), **«Помощь»** (установка с
нуля: Python → Ollama → модель → первый диалог, плюс подбор модели под
объём видеопамяти), **«FAQ»** (частые вопросы), **«Скачать модели»**
(открывает каталог `ollama.com/library` в браузере) и **«Запустить cmd»**
(открывает системную командную строку и окно-шпаргалку по командам Ollama
— `ollama list` / `pull` / `run` / `ps` / `rm` / `show` … с пояснениями и
примерами). Справочные кнопки открывают отдельное окно с прокручиваемым
текстом; тексты — в `help_texts.py`.

## Язык интерфейса (RU / EN)

Переключатель **RU / EN** в правом верхнем углу. Весь интерфейс
переводится на лету — без перезапуска, — а состояние (сцена, история
чата, введённый текст, настройки, свёрнутые панели) сохраняется.
Переключатель заблокирован во время генерации. Выбор языка запоминается в
`settings.json` (`ui_language`).

Язык влияет и на **скрытые промпты**: в режиме EN требование «пиши только
по-русски» заменяется на «только по-английски», а служебные заголовки в
промпте (`## Персонаж:` → `## Character:`, `Биография:` → `Biography:` и
т.п.) и промпт «бегущей памяти» — тоже английские. Пресеты-примеры не
переводятся (это данные пользователя). Все строки интерфейса и хелперы
для переводимых данных — в `i18n.py`; тексты справочных окон — в
`help_texts.py` (по два языка).

Обе боковые панели можно свернуть — чат расширяется на всю
освободившуюся ширину (можно свернуть и обе сразу).

- **Правая** (Logs / Память): компактная **«›»** в шапке самой панели.
- **Левая** (вкладки Сцена / Настройки): компактная **«‹»** слева от
  переключателя вкладок.

Когда панель свёрнута, на её месте остаётся узкая вертикальная полоска
(**«‹ Логи»** / **«› Сцена»**) — клик по ней разворачивает панель
обратно. Оба состояния запоминаются между запусками. Кнопки «Optimal» /
«Очистить» на вкладке «Настройки» состояние панелей и промпт памяти не
трогают.

Кнопка **«Очистить всё»** в колонке кнопок (под «Очистить») одним
нажатием сбрасывает чат, бегущую память и панель Logs (пресеты и
настройки не трогает) — в отличие от «Очистить» рядом, которая чистит
только
чат + память.

Справа от чата - панель с переключателем **Logs / Память**:

- **Logs** — сырой дамп каждого запроса в Ollama (model, весь список
  messages, options и т.д.) и полного ответа; не редактируется, кнопки
  **«Очистить»** и **«Экспорт…»** (сохранить весь лог в .txt).
- **Память** (вкладка есть только в режиме диалога) — «бегущая память»,
  собирается **послойно**, чтобы не ломаться на долгих диалогах:
  - **раз в N ходов** (N в Settings, «Память: пересборка каждые N ходов»,
    по умолчанию 6) отдельным **скрытым запросом** сжимается **только
    последний сегмент из N ходов** в короткую сводку. Уже собранные
    сводки повторно не пересобираются;
  - когда недавних сводок накапливается больше трёх, самые старые
    отдельным запросом **вливаются в «долговременную» память** (выявляются
    и сохраняются самые важные события, мелочи отбрасываются). И так по
    кругу;
  - за счёт этого вход каждого скрытого запроса **ограничен и от длины
    диалога не зависит** — раньше запрос рос вместе с историей и в какой-то
    момент переставал влезать в контекст, после чего память замолкала;
  - в промпт подставляется долговременная память + последние сводки;
    дословно добавляются только ходы после последнего рубежа.
  - Кнопки: **«Промпт памяти»** (своя инструкция для сводки сегмента,
    сохраняется), **«Пересобрать»** (собрать память заново тем же
    послойным механизмом, с прогрессом), **«Применить»** (взять текст поля
    как долговременную память), **«Экспорт…»** (сохранить память в .txt).
    Скрытые запросы видны в Logs (`ЗАПРОС (память: ходы a–b)` /
    `(память: уплотнение)`). `N = 0` — выключить. «Очистить» сбрасывает
    историю и память.

Ввод в режиме **диалога** разбит на два поля: **«Твоё действие»**
(показывается в чате курсивом, при недоступности курсива — в `*…*`) и
**«Твоя реплика»** (только речь). Отправить можно, если заполнено хотя
бы одно; горячая клавиша — Ctrl+Enter. В чате действие и речь одного
хода разделены пустой строкой, а ход собеседника отделён от твоего
двумя. Настройка
**«Раздельный ответ: действие + речь»** (Settings, включена по
умолчанию) заставляет и модель отвечать так же — через формат JSON от
Ollama: сначала строка действия/чувств курсивом, затем реплика. Цена —
в этом режиме ответ появляется целиком после генерации, без
посимвольного стрима; выключишь — вернётся стриминг и обычный текст.

В этом же режиме работает **защита от повтора реплики**: штрафы Ollama
за токены смотрят лишь на последние ~64 токена и не замечают, что
персонаж почти дословно повторяет фразу, сказанную пару ходов назад
(при этом действие каждый раз новое). Если речевая часть ответа слишком
похожа на одну из последних реплик персонажа, приложение молча
перегенерирует ход (до двух раз), расширив окно штрафа, чуть подняв
температуру и сменив seed. Текстовую пометку об этом в саму реплику
персонажа **не добавляет** — это ломало бы иммерсивность и
последовательность диалога; сработка видна в строке статуса (пока идёт
перегенерация) и всегда — постоянной записью в панели Logs (заголовок
КАПСОМ, чтобы не потеряться среди обычных запросов). Если и после
повторов фраза всё ещё похожа — остаётся последний вариант как есть, а
сама попытка отмечена в Logs.

В режиме **истории** этих двух полей нет — там одно свободное поле
«Указания к истории / правки». История теперь накапливается: пустое
поле = «напиши историю» на старте или «продолжай» дальше; текст в поле
= указание/правка (можно остановить генерацию и подкорректировать ход).
«Очистить» начинает историю заново. JSON-формат к историям не
применяется.

Как только что-то уже написано, кнопка **«Сгенерировать историю»**
становится **«Продолжить историю»**. По нажатию сначала — отдельным
скрытым запросом (или несколькими, если написанного слишком много для
одного) — всё, что написано СТАРШЕ последнего хода, сворачивается в
краткий пересказ, примерно как уплотняется память в диалоге; статус
«📖 пересказываю историю кратко…» показывает, что идёт работа. Сам
последний написанный ход при этом пересказу не подвергается — уходит
модели дословно, вместе с пересказом всего, что было раньше. Это важно:
без дословного «хвоста» модель видела бы только сухую сводку в
несколько предложений и не знала бы точного места и стиля, с которого
продолжать — на практике это выглядело как «начинает заново», а не
продолжает. Дословный хвост решает эту проблему; вдобавок сама просьба
о продолжении теперь явно требует двигать сюжет дальше, а не
пересказывать и повторять уже написанные сцены. Раньше (до этого
пересказа вообще) при каждом продолжении в контекст уходила вся история
целиком как есть — на длинной «максимально подробной» истории это
быстро упиралось в лимит контекста; теперь запрос остаётся компактным
независимо от того, сколько уже написано. Полный текст истории при этом
никуда не девается — пересказ используется только «под капотом» при
сборке запроса, в чате и в экспорте всегда виден весь оригинал.
«Очистить» / «Очистить всё»
сбрасывают и кнопку обратно на «Сгенерировать историю», и накопленный
пересказ.

При генерации **длинных** историй (особенно с «Размер истории:
максимально подробно, без ограничений по длине») модель иногда
зацикливается — начинает повторять одни и те же абзацы снова и снова, не
обязательно строго по кругу (иногда это ротация из нескольких похожих
кусков вперемешку, вплоть до вставки «поддельных» заголовков глав) — та
же причина, что и с повтором реплики выше: штраф за повтор слишком узкий
для такой деградации. Такое
приложение тоже ловит прямо по ходу генерации: оборвёт зациклившийся
кусок, аккуратно обрежет в чате лишние повторы (не потеряв уже
написанное до них) и молча попробует продолжить с этого места ещё раз
(до двух раз) — так же без текстовых пометок в самой истории, только
статус во время перегенерации и постоянная запись в Logs (капсом в
заголовке). Если зацикливание не отпускает даже после повторов —
остановится на последнем чистом месте молча (для истории), а событие
всё равно останется в Logs; дальше можно продолжить вручную кнопкой
«Сгенерировать».

Генерацию можно прервать кнопкой «Стоп» (частичный ответ остаётся в
чате и в истории с пометкой), а диалог - сбросить кнопкой «Очистить»
(выбранные пресеты при этом не трогаются). Кнопка **«Экспорт…»**
сохраняет текущий диалог / историю в **.txt** или **.docx** (с шапкой
сцены; действия — курсивом / в `*…*`). Для `.docx` нужен пакет
`python-docx` (входит в `requirements.txt`); для `.txt` — ничего.

Копирование/вставка работает во всех полях (в т.ч. в модальных окнах)
при любой раскладке: Ctrl+C / V / X / A по физическим клавишам, плюс
контекстное меню по правой кнопке мыши (Вырезать / Копировать / Вставить
/ Выделить всё).

## Установка (Windows)

1. Поставь Python 3.11+ с [python.org](https://www.python.org/downloads/)
   (в установщике оставь галочку "tcl/tk and IDLE" - она включена по
   умолчанию, это даёт нам Tkinter бесплатно).
2. Поставь [Ollama](https://ollama.com) и скачай хотя бы одну модель:
   ```
   ollama pull llama3.2
   ```
   (или любую другую - какая влезет по видеопамяти/RAM, это не важно
   для кода приложения, модель выбирается прямо в интерфейсе).
3. В папке проекта двойным кликом запусти **`setup.bat`** - он сам
   создаст `venv` и поставит зависимости. (Вручную то же самое:
   `python -m venv venv` → `venv\Scripts\activate` →
   `pip install -r requirements.txt`.)

## Запуск (без консоли, двойным кликом по .bat)

- **`run_app.bat`** - запускает приложение (окна консоли нет).
- **`run_app_debug.bat`** - то же, но с видимой консолью: если
  приложение не стартует, здесь виден текст ошибки.
- **`run_tests.bat`** - прогоняет `test_logic.py`, окно остаётся
  открытым с результатом.
- **`setup.bat`** - разовая настройка окружения (см. выше).

Все .bat сами переходят в свою папку и используют `venv`, если он есть,
иначе системный `python` из PATH.

Ручной вариант для разработки:

```
python test_logic.py   # прогон тестов: каждый с описанием, в конце ИТОГ
python main.py          # запуск самого приложения
```

`test_logic.py` печатает по строке на тест (номер + краткое пояснение +
`OK` / `УПАЛО`), а при падении — тип ошибки и точную строку `assert`.

Ollama должна быть запущена (обычно она сама поднимается в трее после
установки; либо вручную `ollama serve`).

## Сборка в один .exe

Проще всего — двойной клик по `build_exe.bat` (или вручную):

```
venv\Scripts\python.exe -m PyInstaller --noconfirm OllamaRP.spec
```

Готовый файл — `dist\OllamaRP.exe` (~15 МБ, один файл, портабл): двойной
клик запускает приложение без установленного Python на машине
пользователя. Настройки и пресеты приложение само создаёт в
`%APPDATA%\OllamaRP`.

`OllamaRP.spec` уже собирает данные `customtkinter` (темы/ассеты — без них
exe падает на старте) и `python-docx` (для экспорта в `.docx`). Первая
сборка без spec делалась так:

```
pyinstaller --noconfirm --onefile --windowed --name OllamaRP ^
  --collect-data customtkinter --collect-data docx main.py
```

Альтернатива `--onefile` — `--onedir`: получается папка `dist\OllamaRP\`
(её целиком копировать как портабл), стартует заметно быстрее, но это не
один файл. Python для самой сборки на машине разработчика всё равно нужен.

## Структура проекта

- `i18n.py` - локализация RU / EN: `get_lang()` / `set_lang()`, `t(key)`
  для строк интерфейса, хелперы (`block_title` / `field_label` /
  `inf_label` / `inf_help` / `think_labels` / `story_size_choices`) с
  английскими переводами данных из `blocks.py` / `inference_spec.py`.
  Без tkinter
- `models.py` - Character / Protagonist / Environment / Scenario /
  SystemConfig как простые dataclass'ы (у всех есть `id` + `name`).
  У Character есть `biography`. Плюс `InferenceConfig` - параметры
  генерации (не пресет, один объект), с `to_options()` для payload;
  UI-поля `left/right_panel_hidden`, `ui_language`, `last_model`
- `inference_spec.py` - описание полей вкладки Settings (label, тип,
  подробный help) на русском. Чистый модуль, без tkinter
- `storage.py` - сохранение/загрузка пресетов в JSON (%APPDATA%/OllamaRP),
  `upsert_*` (повторное сохранение под тем же именем/id перезаписывает) и
  `delete_*`
- `blocks.py` - единое описание блоков (`BLOCK_SPECS`): заголовок,
  dataclass, методы хранилища, набор полей формы, стартовый пример.
  Без зависимостей от tkinter
- `prompt_builder.py` - сборка system-промпта: [наталкивание на ризонинг,
  если `reasoning_nudge=True`] → конфиг-промпт → инструкции режима
  (dialogue / story) → [JSON-инструкция, если `structured_dialogue=True`]
  → главный герой → персонаж(и) → окружение (только dialogue) → сценарий
  → параметры истории (только story). Все билдеры принимают `lang="ru"`
  (по умолчанию — русский, старые вызовы и тесты не меняются); при
  `lang="en"` — английские версии констант и заголовков блоков. Плюс
  `STRUCTURED_DIALOGUE_SCHEMA`, `build_segment_summary_messages()` /
  `build_consolidation_messages()` (послойная память: сжать один сегмент /
  влить старые сводки в долговременную голову),
  `build_field_generation_messages()` (запрос «придумай одно поле
  карточки»), `estimate_tokens()` / `next_num_ctx()` (грубая оценка
  размера запроса для предпроверки контекста), `is_duplicate_speech()`
  / `speech_of()` / `norm_line()` (детектор почти дословного повтора
  речевой части хода — используется анти-повтором в structured-режиме)
  и `find_repeat_loop()` (детектор зацикливания текста — ищет не строгий
  период, а похожие абзацы где угодно в недавнем окне, чтобы ловить и
  ротацию нескольких шаблонов вперемешку; используется анти-зацикливанием
  в обычном live-стриме: диалог без раздельного ответа, история, чат)
- `ollama_client.py` - вся сетевая работа с Ollama: список моделей,
  `model_capabilities()` (POST /api/show → есть ли `thinking`), стрим
  чата с `options` / `think` / `keep_alive` / `format`
  (`response_format`), прерывание через `threading.Event`, колбэки
  `on_request` (payload в Logs) и `on_thinking` (размышления — из поля
  `message.thinking` И из инлайновых `<think>…</think>`, склейка тегов —
  `_ThinkSplitter`, отключается флагом `strip_inline_think`);
  `parse_structured_reply()` — JSON-ответ → `(action, speech)`;
  `normalize_messages()` — схлопывает подряд идущие роли (иначе шаблоны
  Mistral/Ministral падают с «roles must alternate»); текст HTTP-ошибок
  Ollama пробрасывается в `OllamaError`
- `preset_ui.py` - окна управления пресетами (список + форма
  создания/редактирования; кнопка «Сгенерировать» у полей —
  `chat_stream` в потоке + `build_field_generation_messages`)
- `help_texts.py` - текст окон «О приложении» / «Помощь» / «FAQ» /
  «Шпаргалка по командам Ollama» на двух языках (`blocks(name)` → список
  блоков `("h"|"q"|"p"|"li", str)` под текущий язык), без tkinter
- `gui.py` - главное окно на CustomTkinter (селекторы пресетов + чат +
  панель Logs)
- `main.py` - точка входа
- `test_logic.py` - тесты для всего, что не требует GUI/сети

## Файлы данных (%APPDATA%/OllamaRP)

- `characters.json` - персонажи (поле `biography` добавлено позже; старые
  записи без него грузятся, оно становится пустым)
- `protagonists.json` - «Главный герой (Вы)»: имя, биография, внешность,
  характер
- `environments.json` - локации (поле `name` добавлено позже; старые
  записи без него грузятся нормально, `name` становится пустым)
- `scenarios.json` - сценарии (то же про `name`)
- `system_configs.json` - конфигурационные промпты: общие правила
  поведения модели (язык, длина ответа и т.п.), не привязанные к
  конкретной сцене
- `settings.json` - параметры генерации со вкладки Settings (один
  объект, не список). Незаданные поля хранятся как `null` и в запрос не
  попадают. Нет файла -> берётся рекомендованный набор
  (`models.OPTIMAL_INFERENCE`)

Поля «Размер истории» и «Дополнительные детали» (story-вью) не
сохраняются - живут только в текущей сессии.
